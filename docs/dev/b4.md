# B4 removals: the backup tool and the per-unit recipe

Tools under `scripts/b4/`. They only prepare, check and report; a removal job still decides what goes. Nothing here runs in CI.

## The one command

```
node scripts/b4/unit.mjs <unit> --entries <file> [--grep <text>]... [--test <folder>]... [--base origin/main] [--to <backup root>] [--plan]
```

Run it in the job's worktree. The entries file lists what goes, one per line (blank and `#` lines skipped): `path` (a file), `dir/` (every tracked file under it), `path#name` (one export of a file that stays, for the dead-export check only). `--plan` prints the steps without running them. The unit stops at the first failing step and prints the problems.

| # | Step | Passes when |
|---|---|---|
| 1 | backup | every removed file is copied to `<backup root>/<unit>/` (same relative paths, default `scratch/backups`) with `MANIFEST.txt` (sha256, bytes, lines, last commit, path). Refuses if that folder exists. |
| 2 | git rm | the files and `dir/` contents are gone from the index |
| 3 | dead exports | no kept file refers to a removed path or `path#name` |
| 4 | git grep empty | each `--grep` text (a path, export name, setting key or DOM flag, fixed string) has no hit outside `docs/history` and `CHANGELOG.md` |
| 5 | shrink-only lists | none of `docs/merge/{core-module-refs,global-exceptions,legacy-exports,legacy-oversize,layout-nonliteral}.txt` has an entry the base lacks, and none still names a removed path (take those lines off in the same PR) |
| 6 | code map | `npm run codemap`, then `node scripts/codemap/cli.mjs --check` |
| 7 | touched tests | `node --test "<folder>/**/*.test.js"` for each `--test` folder; at least one is required. CI is the full gate. |

Not covered by the command: `npm run check`, the CHANGELOG line, the list of deleted tests in the PR, and the unit's own extra checks in the B4 plan (screenshots, replay fuzz). `docs/merge/removed-exports.txt` is grow-only, so append removed export names to it by hand.

## The pieces alone

- `node scripts/b4/backup.mjs <unit> <file with one path per line> [backup root]`.
- `node scripts/b4/dead-exports.mjs <entries file>`: reads every relative specifier written as a string in tracked `js`, `mjs`, `cjs`, `json`, `css` and `html` files, so static imports, re-exports, `import('./x.js')` and `new URL('./x.js', import.meta.url)` are caught, plus `path#name` imports. It also prints the files with a computed specifier (`import(variable)`, a template with `${}`, a `new URL(variable, import.meta.url)`): grep those by hand, the tool cannot resolve them.
- A match is by path, so a name that only appears in text (a comment, a string that is not a path) is for the `--grep` step.
