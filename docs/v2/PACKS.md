# Packs

A pack is a JSON file containing world data. It can provide places, routes, a calendar, weather, events, currency, starting state, screens and data modules. The [Ersveil open-world example](../../examples/packs/ersveil/pack.json) shows a larger pack; [Ersveil](ERSVEIL.md) describes how to play it.

A pack can give your character a **rank** with `"content": { "you": { "rank": { "label": "Guild rank" } } }` (the label is 1 to 30 plain characters). Only a story with such a pack has a Rank in Your look: Home shows it first under the label ("Guild rank"), Story Director's Status card has a row for it, and the narrator is told to write `~ you rank: …`. The first enabled pack that declares it wins. With no such pack there is no rank anywhere and `~ you rank:` is not used; a rank already kept stays and returns when the pack is on again. The Ersveil example uses "Guild rank".

Import a file under **Settings → Tabs & Packs → Import pack file**. A pack with an existing id replaces that installed pack. Start a new chat to use its starting state.

For the format and limits, see the [authoring-kit reference](../../authoring-kit/reference/PACK-FORMAT.md) and [limits](../../authoring-kit/reference/LIMITS.md). [Data modules](DATA_MODULES.md) covers their definitions and examples. The authoring kit's checker uses Story Block's own pack validation.

Story Block 2.31.0 adds optional `ripples` and `content.names` sections and event `decision` groups. `ripples` has ordered powers (`id`, `name`, `base`, optional aliases, factions, givers, NPCs and standing), optional `tiers`, `caps`, `worldDirections` and `standingModule`. `packs.ripples({ pack })` selects an enabled pack; with no pack it returns the first table. The Director scores the table. `content.names` is one object of culture ids to `{ regions, given, family? }` plus optional `banned`; `names` and `banned` are reserved keys. A bad section is ignored with a pack warning; other invalid fields still refuse installation. Director's names part is needed for suggestions.

Once events may share a `decision` slug within a pack: the due alternative is selected again on the state before its stored receipt after an earlier Re-read, swipe or deletion. A decision group should contain mutually exclusive conditions. `packs.rippleChoice` checks the requested pack and claimant ids before using Director's sway; if the provider or the matching table is unavailable, it returns the pack's specified fallback. Older Directors use only their first table, so a preceding unrelated table causes the fallback until scoped sway is supported.


Event conditions can use `region(name, ...)` (Story Block 2.31.1): true when the scene's place is in any of the 1 to 16 named regions (exact names, as `query('scene.place').region == name`; false with no place). It replaces a chain of `||` over regions, so one event can cover several regions and fire once. Each name is at most 200 characters; the whole condition keeps its 1000-character limit.

With the Settings feature **World events** on (off by default), a legacy event's `when` can also call `condition('name')` or `condition('name', 'ref')`, `active('event-id')` and `fact('text')`; the install check reads these calls whatever the switch says (it is structural), and the switch only decides whether the world uses them. Spec events (author spec v0.13 §3) are not written in `content.events`: they go in `content.worldEvents`, see the next section.

Rules packs for RPG Battle cannot be imported. Keep existing RPG Battle chats on the previous versions.

## Pack format 3

Pack format 3 is what the suite writes and reads today. A pack says so with `"format": 3`; a pack without `format` is read as format 2 and loads the same way, and a pack whose `format` is newer than 3 is refused (`FORMAT_NEWER`, "update the suite").

- **Version check.** `"requires": { "suite": "^0.1" }` is a range checked against the suite's own version (0.1.0). `requires.storyBlock` is the older name: it still loads, and holds when its range fits either the host compatibility number older packs name (2.33.0) or the suite version. A pack gives one of the two, not both. Capabilities (`requires.capabilities`) are checked against what the running suite provides, as before; `chronicle-lasting` and `data-modules-v1` are provided, and the retired `story-director` is no longer a capability (the Director's clock is the `director` domain).
- **Skills use the Combat Rules v1 words.** A cast skill (`content.cast[].skills`) and a skill set skill (`content.rpg.skillSets[].skills`) take `stat` one of `str vit agi dex int wis cha` (`luk`, which earlier packs wrote, is read as `wis`), `type` one of `attack area defence evasion movement heal support utility` (left out it is `attack`; `combat` is read as `attack`; a utility skill is for the story only), and `uses` `sp` or `mp` (`stamina` and `mana` are still accepted and mean the same). A cast skill's `rank` is one of `novice apprentice adept expert master grandmaster legend`; the skill that joins a party starts at that rank. A skill set's skills have no rank (the New character window starts every one at Novice).
- **Formula.** `content.rpg.formula` is `"v1"` (`"standard"` is the older word for it; `"classic"` is refused). A pack cannot tune combat numbers: `content.rpg.numbers` is accepted with a warning and left out.
- **Kinds nothing reads are left out.** `content.creatures`, `shops`, `recipes`, `quests`, `races`, `talents`, `presets`, `terms`, `ranks` and `crafts`, and the top-level `layouts` and `screens`, are accepted with a warning (`IGNORED_KIND`, `IGNORED_FIELD`) and left out of the pack as the game reads it; the file you wrote is kept as it was. (`content.rpg.ranks` and `content.you` are different and stay; so do a data module's own `screens`.)
- **Foes.** `content.foes` is a bestiary: `[{ "name", "aliases"?, "tier", "level"?, "about"?, "tags"? }]`. `tier` is `mob`, `minion`, `standard`, `elite`, `boss` or `apex` and is required; `level` is 1 to 99; `about` up to 240 characters; up to 8 aliases and 8 tags. When the fight pre-check reads a typed attack and a group it finds is a listed foe (by name, alias or a plural of either), the fight uses the listed tier and, when one is listed, the listed level instead of what the model said. A person's own stated Level still wins over a listed one, and a foe that is not listed keeps the pre-check's tier and level. Nothing else reads `content.foes` yet.

## World conditions (`content.conditions`)

Optional list of the named states of the world a pack declares: `{ "name": "grain-dear", "scope": "region", "fades": "1 season", "means": "Bread and fodder cost far more than usual." }`. `name` is lower-case words joined by `-`; `scope` is `place`, `route`, `region` or `realm`; `fades` is how long it lasts by default (`10 days`, `1 season` = 90 days, `2 months` = 30 days each, `until cleared`; left out = until cleared); `means` is one plain sentence (at most 300 characters). Only declared names can ever be set, and only while the reader has the feature `story-director.world-events` on (off by default). Kept only when given, so a pack without it normalizes as before. The store (`chronicle.conditions`) and its commands are in `modules/world/chronicle/conditions/`. A condition is set and cleared only at a ref of its own scope (a region condition on a region: clearing it clears it for every place in it; a place ref on it is refused), named by id, name or alias; a realm is a `realms` entry (a region in no realm is in the Wilds); a route by its `name` (default `From-To`). A timer is whole days, at least one. A condition cleared at a ref is not set there again the same day, by a world line or by the daily step. A `placeStatus` condition is not set by a world line or the Director where a protected cast member lives (or in a district under that place); an authored event may. With the switch on its `routes` effect (`blocked`, `×0 speed`, `×N speed`) and a `placeStatus` at a route's end (×2) change how fast news travels; its `means` and `prices` are told to the narrator in the world note (prices as written, never computed). News (world.heardHere) travels at the route class speeds of spec §1 from `routeKinds` (relay-road 135 km a day, road 60, trail 35, river 60, pass 60, sea by `hours` else 110; `none` never); a route kind with no class goes at the reader's courier setting.

## The world pack (`content.worldEvents` and friends)

The install check accepts and keeps every part of the world-pack author spec (v0.13), as optional kinds under `content.*` with no format bump: `lore`, `placeKinds`, `routeKinds`, `realms`, `powers`, `scores`, `worldEvents`, `templates`, and, extended, `conditions` (`effects: { prices, routes }`, `placeStatus`), `places` (`id`, `weight`), `routes` (`name`, `hours` on a sea route) and `cast` (below). The check is structural: it does not depend on the World events switch; with the switch off the parts are kept and nothing uses them (outputs are as before). It runs in full when a pack carries any of the eight kinds above (`lore`, `placeKinds`, `routeKinds`, `realms`, `powers`, `scores`, `worldEvents`, `templates`); a pack with none keeps the old rules (free-word kinds, `:` in a region name).

What it refuses, each with a Problem naming the path: a place or route kind that is neither mapped in `placeKinds` / `routeKinds` nor an engine class, or a mapping to a class that does not exist; `@` or `: ` in a place, route, region or realm name; one id for a realm, region and place; two routes between the same two places that are not each named, or a duplicate route name; a condition, ref, power, score, event, template or cast id an event, template, anchor, gate or effect names that the pack does not define, or a ref of the wrong scope; a legacy `content.events` id in a `fired:`, `ended:`, `lapsed:` or `stage:` anchor (and an id used in both lists); placeholders (`@place`, `@region`, `@route`, `@realm`) in a one-off or chain stage or of the wrong scope; an event with no `ends_when` (it is `"instant"` or `{ for, any_of }`); a recurring event with a window or no cooldown; a chain stage with no `stage:` entry; thresholds (`power:<id> >= N`, `score:<id> <= N`; only `>=` and `<=`, ids not names, N inside the range) anywhere but `requires`, `requires_any` and `ends_when.any_of`; modifiers that are not `×N`; a negative outcome weight; a power or score named in a weight or in `effects.powers` / `effects.scores` that is neither an id nor a unique name or alias; price effects of 0 or below, or naming something that is no item tag or market category; a template with cast effects, or one that sets a place status where a protected person lives; hidden lore with no gate, a lore gate naming a stage or person that does not exist.

Warnings (the pack still installs): a `fact:` nothing in the pack writes, a place status that lasts until cleared with no clearing template or event and no duration, a power also declared in `ripples.powers`, a season anchor neither built in nor in the pack's weather, `hours` on a route that is not a sea class, a gate on lore that is not hidden, and a reference (`died:`, `effects.cast.who`, a lore gate) to a person who is written but was refused.

**Cast.** A cast whose entries carry `kind` (`companion` or `figure`) is read as the world pack's (spec §8): a figure needs only `id`, `name` and `kind`, and may carry any companion field; `ties.with`, `keyRelationships.id` and gates name cast ids; stages are `{ name, needs: [{ meter, at }], text, milestone? }`; secrets are `{ id, gate, text }` or the old fields, never both. **One bad entry is refused alone** (a Problem naming the person and the field; the rest still load), and a tie or key relationship that points at a refused person (written, but refused) is dropped with a Problem while its owner stays; an id written nowhere still refuses the person that names it. Events and lore that name a refused person get a Problem too (the daily step skips an unknown `who`). At most 64 people (the rest are left out with a Problem) and 6 aliases. An entry without `kind` is checked as before (the old rules, all or nothing).

**Event moves, people with You, learned secrets (v0.14.4-v0.14.9; WEV10).** An `effects.cast` entry may carry `from`: a place id (the move or death applies only if the person is in that place or a district under it at the tick) or `"anywhere"`; a move without `from` applies only while the person's latest base is still their start (a death without `from` applies anywhere). An event may say `"even_in_party": true`. A spec secret and a hidden lore entry may carry `writes_fact` (a fact id; it counts as written by the pack), a lore entry an `id`; `learned:<cast id>/<secret id>` and `learned:lore/<entry id>` are anchors (in requires, requires_any, window.after, ends_when, likelier_if / less_if keys, pre_empted_by and gates). Refused: a `from` that is no place of the pack, an `even_in_party` that is not true or false, a `learned:` naming an unknown person, secret or lore id (or a lore entry that is not hidden), `writes_fact` on an old-shape secret (that person is refused alone) or on a lore entry that is not hidden. Warned: a named move without `from` whose person starts outside the event's `where` (its place, region or realm). With the switch on, the daily step does not move someone with You (a party member who has not left, or someone in the scene): the Journal says "<name> stays with You — <event title>" and the move waits, applied at the first tick they are no longer with You if the event still holds it (`from` checked again), else dropped. A death of someone with You is refused (Problems) unless `even_in_party`; then the next replies' world note carries "<name> dies here: <summary>" (first in its pinned head), applied when NPC State records the death, else by code after 3 replies (Journal line and Problems). Named moves apply before the same event's place-status evacuation, which leaves the people they placed. The step's moves go into the cast store (`where`, `doing`, a `base` slot, `since`; a journey is cleared); the day planner is told a person's base and routine, its moves away from the base are dropped, and no goal pull starts for them. A narrator `where:` on a pack person's dossier, a party leave (a stays record, "waits for You at <place>") and a rejoin (cleared) are the story's bases. NPC State's opened pack secrets are recorded after the reply's step as `learned:` anchors (and their `writes_fact`), from the next step on. Not built: the open-template cast move (open templates are not built), the Director judge of "react, not resolve" (the planner's rule and a code guard for the certain cases are built: the brief carries the rule, and a beat, clock or agenda naming an Active event with one of its outcomes, or an outcome by an id-like name, is left out of the plan with a note; the free-text judgement waits for the judge), and a source for `learned:lore/…` (nothing learns lore yet); with the switch on a person's spec-form secrets reach NPC State (NSSPECSEC): withheld from the narrator while the gate is closed, `(may come out)` once it opens, learned by a `~ reveal` line with a quote; the Director's brief lists the unlearned ones under a never-hint rule. With the switch off they are dropped as before.

**The Director judge and the arc world note (WEJUDGE; behind `story-director.world-events`).** After the arc planner answers, one Quick call judges its beats, clocks and agendas against the world state, the protected cast, the hidden lore's titles and the lore digest: accept, reshape (a corrected line, read again by the plan reader and the code guard) or refuse (the adopted note when it decides an Active event, else a short reason). Code has the last word, a failed call leaves the guard's result, and the verdicts and the arc's world note (about 120 tokens) are stored with the arc and sent to the narrator as \"Arc and the world: ...\" while the arc runs. Write good keys on lore entries: the digest sends every title but the full text only of entries whose keys match the scene's place. Hidden lore reaches the judge as a title only.

**Open templates (v0.14; WEOPEN, behind `story-director.world-events`).** A minor template that carries `open: { menu, writes_facts? }` (with an optional `fallback` in the usual `sets` / `clears` form and a `per` budget, default "region per season") is an **open template**. Code still rolls and places it (cooldown, density, the `per` budget and the placeStatus guards are decided when the slot rolls); the Director then fills in the happening on the **Quick** profile, from the menu only: the answer is JSON `{ name, summary, people, effects }` with `effects` among `powers`, `scores`, `set` (`{ condition, for }`), `clear`, `ladder` (`{ direction, steps }`), `cast` (`{ id, to }`, a non-protected figure to a place in the region; with You the move waits) and `fact` (one of `writes_facts`). Code checks every pick against the menu and the guards (protected people and places, no condition an authored event, lore gate or secret gate reads unless the condition is `open: true`, a fact only through `writes_facts`); a refused answer gets one retry with the errors, then the template's `fallback` (none: nothing happens). Each outcome (ok, retry, fallback, nothing) is a Problem line. **Canon:** the answer is stored once per slot (campaign seed + day + template id + place id) in the chat's ledger (`chronicle.ledger.open`, the newest 64), in the message before the reply, so a swipe, delete, Re-read, reload or a rewind in the same session reuses it and never asks again (a rewind after a reload, past the message that stored it, asks again); the day record (`chronicle.daily.slots`) points at it by key. **Asked ahead, never blocking:** the call starts in the background when a slot is rolled or predicted (a dry run of tomorrow), one batched call for up to 4 slots (a retry is a second call; both are counted in `chronicle.ledger.open.calls`); a slot whose answer is not stored when the day crosses waits (`chronicle.daily.pending`) and is applied on the reply after the answer is stored, or uses its fallback after 3 world days; the 5th and later slots of one step use their fallback. A busy or missing model call is not a failure: the slot is asked again on a later reply. Only minor, code-rolled templates are open; **generated arcs (`arc` on an open template) are not built**. Off the switch nothing here runs.

**Install check up to spec v0.14.10 (WEPACK2).** Structural, never behind the switch. The check now accepts and keeps: a condition's `open: true`; `content.regions` (`[{ id, name, aliases? }]`; every place's region and the start scene's region must be a declared id; with no `regions` one warning `REGIONS_UNDECLARED`, not a refusal; a realm that lists an undeclared region is warned); the words `place`, `region`, `route`, `realm` are refused as the id of a place, region, realm or route; `start.world` (`{ set: [condition strings with a duration], facts: [fact ids] }`, checked, kept on `start`, its facts count as written); `cond@@place` read as `cond@place`; the anchors `date:<year>-<month>-<day>` (a month number or the calendar's month name; an unknown name in the pack's own calendar is refused, a day past the month or a month the calendar lacks is warned) and `arc-ended:<template id>@<ref>`, and the one-off shorthand `"on": "date:..."` (refused beside `window`, `chance`, a certainty other than set-in-motion, or on a recurring event or chain stage); outcome weights as sums and differences of numbers and `power:` / `score:` / `standing:` refs (a `*`, brackets or a negative literal is refused); thresholds as `likelier_if` / `less_if` keys (still refused in `pre_empted_by`); templates with `requires`, `requires_any`, `likelier_if`, `less_if`, `per` (`"region per season"`), `open` (a menu of `powers`, `scores`, `set`, `clear`, `ladder` with `direction`, `cast`, and `writes_facts`, every id checked, `delta` within -10..10), `arc` (`{ steps: [2, 4] }`, only with `open`) and `fallback` (`sets` / `clears`); gate terms `set:` / `cleared:` that name a place; and a cast `age` that is a whole number (kept as its digits) or text. A protected person in an open cast menu is a warning. Size, text and cast limits are unchanged (a pack over 512 KB is still refused). The engine side of these is built in the next paragraph (WEFIX1), except `arc` (generated arcs are not built). Open templates are built (see above), without `arc`.

**Engine side of the spec rulings (WEFIX1; behind `story-director.world-events`).** The daily step now reads what the check already accepts. *Calendar:* the step is given the chat's calendar (`director.calendar`, else Gregorian). A season anchor (`spring`, `summer`, `autumn`, `winter`) holds while the calendar is in that season (the year split in four as the weather's built-in seasons are: winter around the year's turn; a pack's `weather.seasons` names are not used here); as `window.after` it opens on the season's first day. `date:<year>-<month>-<day>` (a month number or the calendar's month name) holds from that calendar day on, in `requires`, `window.after` and `ends_when`; `"on": "date:..."` is a one-day window at set-in-motion 100% on that calendar day (tempo does not stretch it; a skip across it still fires it). *Odds:* a "N% per season" chance on an event that requires a season anchor is spread over that calendar season's days, not 90 × tempo, so tempo does not change its yearly odds; any other per-season chance is still spread over 90 × tempo days. A chance of 100% per season fires once per stretch (the season, or a 90 × tempo block from the step's first day) on a seeded day inside it, or on the first eligible day after it. Thresholds in `likelier_if` / `less_if` keys are applied (an unreadable one still leaves the event out with a warning); an outcome `weight` is read as a number, a ref (value + 100), or a sum or difference of them, clamped at 0 (`standing:` is the player's favour, which the step does not hold: it reads as 100). *Same day:* a set-in-motion or windowed event whose `window.after` anchor is made later the same day (by an event processed after it) opens that day. *Templates:* `requires`, `requires_any`, `likelier_if` and `less_if` apply (the place is picked first, so `@place` / `@region` / `@realm` read it); a **major** template (resettlement, reconstruction) is rolled by code under the realm's active-major cap and 45-day new-major timer, and takes the timer slot (it does not count as minor density); a major `open` template is still not rolled. *Severity:* only `"severity": "major"` events (the default) use the realm's 2-active cap and the 1-new-major-per-45-days timer; mark recurring pressures `"minor"`. *Deaths:* a protected person is killed only by an authored event that names them in `effects.cast` (never by a template or an open template); a death that is skipped (the person is with You without `even_in_party`, is unmet and not `canDieUnmet`, or is protected and named by something that may not kill them) leaves the outcome's Journal line with "(<name> survived)" appended and a Problems note. *Start and names:* `start.world` is applied once, on a chat's first step: its conditions are set (with the duration written, else the condition's own fade) and its facts written, with no news, no Journal line, no event and no cap or density use; a place status in it evacuates nobody. `content.regions` names are used in `{region}` of a summary and in the world note's and the Conditions card's "at <region>"; stored refs and places keep the region id. Not built: `arc`, and `standing:` weights reading the player's favour.

Names: where an example writes a display name (`power:Princess Wendhild`, `scores: { "Highmark Stability": -10 }`) it is accepted when it names one power or score (id, name or alias); thresholds take ids only. The daily step today keys standings by name, so an id written in `effects.powers` is skipped there with a warning until the engine reads ids.

Not built: the daily step reads `requires` entries with thresholds only after a later engine job (until then such an event installs but the step leaves it out with a warning); seeding NPC State from `companion` / `figure` entries (they have no `about`) is not done here.

## Character bars and skills in a pack

A pack-defined Character keeps the sizes its own block gives. The block field key `scale` (only 2, only on a Character's `health`, `stamina` and `mana` bars, all three together) marks the doubled bars of Story Block's own new Character; marked bars may hold up to 17 stages, other bars up to 10. A Skills block with a `type<n>` field (combat or utility) has up to 80 fields and 22 kinds; a pack's cast `skills` may carry an optional `type` (`combat`, the default, or `utility`; any other value is refused): a utility skill goes into one of the three utility slots, a combat one into a combat slot, and a fourth utility skill is left out (on a return, a Problems line names it). See [RPG.md](RPG.md).

## The cast

`content.cast` lists the people of a world, written by hand. Each is a prepared person who starts somewhere with a goal and a routine and lives off-screen; Story Director brings them into the story by place and routine, or because their goal pulls them to the party, and NPC State Delta makes their dossier from the entry at the first meeting. Until then the reader sees nothing of them. Nameless extras stay the story's to invent. The Ersveil example has twelve (docs/v2/ERSVEIL.md, "The twelve"); the JSON below is a made-up one.

```json
{ "id": "fenna", "name": "Fenna", "aliases": ["the ferrywoman"],
  "about": "Runs the night ferry between Bluewatch and Ashford.",
  "look": "Late thirties, wiry, black hair tied back.",
  "wears": "A tar-stained coat.",
  "voice": "Dry and unhurried.", "personality": "Patient, watchful.",
  "behaviour": ["Care: high - fiercely protective of the ferry's passengers"], "mannerisms": ["Coils a rope when she thinks"], "withYou": "Wary of you until you have crossed twice.",
  "history": "Lost her husband to the weir in 598.",
  "birthday": "Icewane 27",
  "portrait": "fenna.webp",
  "start": { "place": "Bluewatch docks", "goal": "Find out who opened the weir.", "routine": "Works the night ferry from dusk." },
  "drawnTo": ["the weir", "a flood on the river"],
  "meters": { "preset": "companion", "trust": 10 },
  "stages": [{ "id": "regular", "name": "Regular passenger", "needs": [{ "meter": "trust", "at": 20 }] }],
  "fields": { "Trade": "Night ferry" },
  "secrets": [
    { "title": "Her husband's debt", "text": "He owed the smugglers.", "meter": "trust", "at": 20 },
    { "title": "Who she suspects", "text": "She has a name, but no proof.", "when": "the party learns who opened the weir" } ],
  "canDieUnmet": false }
```

- Required: `id` (lowercase letters, digits and dashes, unique in the pack; the person's key is `pack:id`), `name`, `about`, `look`, and `start` with `place` and `goal`. Everything else is optional. `look` is the body only (species, age, build, face, hair, eyes, ears, tail, scars, permanent marks, bearing); `wears` (optional) is what they usually wear and carry: clothes, armour, jewellery, gear on them, and how they wear it. NPC State Delta's dossier puts `look` in the physical appearance and `wears` in the outfit. An older Story Block refuses `wears` as an unknown cast field.
- `personality` is who they are inside, in a few words. Three optional fields carry the rest of what NPC State Delta's own dossier has a place for, so each kind of trait lands there instead of in one long paragraph: `behaviour` (up to 6 lines `Lever: level - effect`; the lever is one of Disposition, Care, Expression, Independence, Conflict, Threat, Analytical, Presentation, Mercy, Loyalty, Drive, Honesty, in any letter case and kept in this form; the level is `low`, `medium` or `high`; the effect is one plain line of at most 120 characters; a lever once for each person; how they generally respond or decide, not how they treat the player character and not their routines) goes to the dossier's behavioural levers; `mannerisms` (up to 4 one-line habits of at most 120 characters, the small recurring things you would notice in a scene) to its mannerisms; `withYou` (text, 320 characters, the size of NPC State Delta's relationship summary: how they treat the player character) becomes its relationship summary at the first meeting, and the story keeps it up to date after that. A key left out (or an empty list) is simply absent, and `withYou` given as empty text is refused like any other cast text; someone already met keeps their dossier. A line that breaks a rule is refused with the person, the line and the allowed words named. An older Story Block refuses the three keys as unknown cast fields.
- Text is plain and one line (line breaks become spaces); `< > { }` are refused everywhere and `|` in names, places, goals, routines and phrases. `aliases` (at most 8) and a name may not repeat another person's in the pack.
- `birthday` (optional) is the person's birthday in the pack's calendar: a month name and a day, with an optional year (`"Icewane 27"` or `"Icewane 27, 1204"`). The month must be one of the pack's `calendar` month names (any letter case; it is kept as the calendar spells it) and the day within that month, so a pack with a `birthday` needs a `calendar`. NPC State Delta's dossier takes it as the person's real birthday (a year, if given, fixes their age); a birthday the story states later still corrects it. A cast entry without one gets a birthday from NPC State Delta as before. Packs without the key stay valid; an older Story Block refuses it as an unknown cast field, so a pack that uses it needs Story Block 2.32.0 or later (`requires.storyBlock: "^2.32.0"`).
- `meters` is `{ "preset"?: id, "<meter>": whole number }`: starting values for NPC State Delta's meters (trust, affection, desire, tension; loyalty, respect, rivalry and approval, which NPC State Delta's built-in presets companion, rival and mentor add; a preset of the pack's own or the reader's; or ones listed here; `preset` is any preset id, checked by NPC State Delta, not here: this host checks only that it is a well-formed id). The built-in preset ids are exported as `CAST_BUILT_IN_PRESETS` (`packs/limits.js`: `companion`, `rival`, `mentor`), for an editor that offers them; a test pins the list against NPC State Delta's own, -1000 to 1000. `stages` have the shape of a meter preset's stages (`id`, `name`, `needs: [{ meter, at }]`, `milestone`; at most 8). `fields` are at most 6 short facts (name up to 40, value up to 60 characters).
- A secret has a `title` and `text` and opens by a meter reaching a value (`meter` and `at`, like a stage), by a story event (`when`, up to 120 characters), or by both, in which case it opens at the meter value or on the story event, whichever comes first; it needs at least one of the two; at most 8. The story never rewrites them.
- `drawnTo`: up to 6 short phrases for what pulls the person to the party. `canDieUnmet`: true lets the story kill them before the party has met them (otherwise only a reader's setting does).
- `gear`: up to 6 of this pack's items (slug or name) the person is known for, kept as the items' ids. Each must be equipment with a gear slot (weapon, body, off-hand, head, cloak, feet, accessory), one item to a slot (an accessory may take two); an unknown item, a non-equipment item, a slot clash, a repeat or more than six is refused with the entry and item named. It does nothing while `story-block.gear` is off. With it on, the person's `+ party` line (or the Ask card's Add to party) also gives them these items, owned by them and put on, as part of the join's one receipt; see GEAR.md "Signature gear".
- Limits (`packs/limits.js` `CAST_LIMITS`): 64 people per pack; about 300, look 600, wears 300, voice 300, personality 600, withYou 320, history 1,200 characters, birthday 80; place 80, goal and routine 200.

- `skills`: 1 to 8 signature skills, `[{ "name", "about", "stat", "uses", "rank", "type" }]`; leave the key out for none (an empty list is refused). `name` 1 to 40 characters, `about` 1 to 120 (one line, no `< > { } |`), `stat` one of `str vit agi dex int wis cha` (required; `luk` is read as `wis`), `uses` `sp` (default) or `mp` (`stamina` and `mana` still accepted), `rank` `novice` (default), `apprentice`, `adept`, `expert`, `master`, `grandmaster` or `legend`. A name once for each person (case and spacing ignored); any other key is refused (`UNKNOWN_FIELD`); the entry and index are named. No rank cap by level: the author decides. With the RPG on, they are put in the person's skill slots **when they join**, as written and marked signature; see RPG.md "Signature skills". `type` (optional): one of the eight Combat Rules v1 types (`attack` by default; `combat` is read as `attack`); a utility skill takes one of the three utility slots (a fourth is left out), any other value is refused.

`packs.castGear({ name })` gives the "Gear:" line for the narrator's cast entry (GEAR.md "Signature gear"). `packs.content({ kind: "cast" })` gives the enabled packs' people in pack order, each as above with `pack` (the pack's id) and `packVersion`, and with no `slug`. The pack list shows "n cast members".

### Portraits

`portrait` names an image file beside the pack. Pick `pack.json` and its images together in **Import pack file** (several files at once), or pick the pack as one `.zip` made by Story Studio (`pack.json` and a `portraits/` folder). Each image must be a WebP, PNG or JPEG of at most 10 MB, named by a cast entry; a pack names at most 32 different files. What is stored is at most 150 KB a picture (NPC State Delta keeps a copy per chat): an image of 150 KB or less is stored exactly as it came, byte for byte; a larger one is decoded in the browser, drawn with its long side at most 1200 px and saved as WebP, with the quality stepped down (then the size) until it is 150 KB or less. An image the browser cannot read, one that is still over 150 KB at the lowest step, one with more than 64 million pixels, one over 10 MB, the wrong type (checked from its first bytes, not its name), not named by the pack or empty is refused with a reason naming the file, and the rest of the import goes ahead. Importing a newer version replaces the portraits it brings; one not picked again stays while the pack still names it, and one the pack no longer names is removed. Removing the pack removes its portraits.

Portraits are kept outside settings, as SillyTavern user files (`user/files/storysuite-portrait-<pack>-<hash>.<ext>`; the hash makes a changed picture a new file, so no browser shows an old one). The pack is stored on the server, so its portraits are too, and follow it to every device; SillyTavern's Data Maid lists them as unused files, so do not delete them there. A portrait file that has gone missing shows as no portrait until the pack is imported with it again. A module reads one with the query `packs.portrait({ pack, file })`: a safe image URL (`/user/files/…`), or null when the pack is not installed, does not name the file, no picture was imported or the file is gone.

### In a character card

A card can carry a pack, its portraits and recommended settings in disabled lorebook entries tagged in their Title/Memo; Story Block offers them when a chat opens (BUILD-A-CARD.md, "Ship your whole world inside the card"). The formats (JSON, plain or in a ```json fence):

- `[storysuite:pack]`: the pack, as `pack.json`. Installed through the same checker and limits as an import (`source: lorebook`); an offer shows for a pack that is not installed or is a newer version than the installed one.
- `[storysuite:portraits]`: `{ "v": 1, "pack": "<id>", "version": "<version>", "files": { "<file>": "data:image/<webp|png|jpeg>;base64,…" } }`. `pack` and `version` must equal the pack's. At most 24 files, 200 KB each, 3 MB together (decoded); each name must be a portrait the pack's cast names and the bytes must be the picture type the address says. They go to the same portrait store as a zip import (so the 150 KB stored limit and the shrinking apply). A file that fails is skipped with a Diagnostics line; more than 24 files or more than 3 MB refuses the entry.
- `[storysuite:settings]`: `{ "v": 1, "settings": { "<owner>.<key>": value } }`, from the allow-list `story-block.rpg`, `story-block.gear`, `story-block.rpgXpRate` (50 to 300, steps of 25), `npc-state-delta.portraitPromptFormat`, `npc-state-delta.scanEvery`. Each owner checks its own values; an unknown key or a value that fails is skipped with a Diagnostics line.

In the Packs list, a pack of data modules and nothing else countable reads "N data modules".

### As a zip

A pack `.zip` holds `pack.json` at its top and the images in `portraits/`, nothing else: a file that is neither is refused and nothing is imported. Also refused, in plain words: encrypted, zip64 or multi-disk zips, a path with `..` (or starting with `/` or `\`), a zip over 322 MB (32 portraits of 10 MB and a pack), more than 322 MB unpacked, a file in it over 10 MB, a `pack.json` over 512 KB, a deflated file over 256 KB that unpacks to more than 100 times its packed size, or more than 40 entries. Stored and deflate are supported; the browser's own decompression unpacks them.
