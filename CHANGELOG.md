# Changelog

## 0.1.0

First release of Story Suite as one extension. It brings together what was Story Block, Story Director and NPC State Delta (now called NPC State). Their own changelogs, with every earlier version, are kept in `docs/history/packages/`.

- **The new view is the default.** Story Suite opens in the new view for everyone: `index.js` hides the old view's chat furniture from the first paint, then mounts the new view as soon as Story Block is ready (`ui/entry/start.js` `startView`; it no longer waits for the Extensions panel). The "new view (preview)" checkbox and the `ui.next` setting are no longer read (the key stays in the settings defaults until the old view is removed). The wand menu entry is "Story Suite"; the old view's wand entry, its two drawer buttons and its strip switch are hidden while the new view shows, and the Story Suite drawer gets the new view's own **Settings** and **Open Story Suite** buttons. The old view is a hidden fallback until it is removed: **Settings › Tools**, switch on **Developer tools**, then **Use the old view** (this device only, kept in localStorage `storySuite.ui.oldView`); it takes the new view away at once, and a ticked "Story Suite: use the old view" row under Extensions is the way back.
- **Settings › Director in the new view.** The Settings overlay now draws the Director page from the live settings: checks (difficulty when none is written, and how strongly and how far feelings move a social check, which are NPC State's), plan spoilers, the world pulse, the planner (when to plan, accept automatically, genre, messages read, longest plan, stalled after, running low, the note), the cast (new faces, unmet people dying), names and initiative (banned names, suggestions, replies before the same person acts, threads elsewhere). Each row reads the stored value over the default and a change writes the same module setting the old view's page writes (`story-director` or `npc-state-delta`), so a value set in either view is the same value; a row whose feature is off is left out and its value kept. Not built, because no setting backs them: "A miss by this much is a success at a cost", "Cast moves: messages read / longest answer" and "Scene spoilers hidden by default" (the scene spoiler is the per-chat switch on Now and in the dossier). "Plan spoilers hidden by default" is the old `Behind the scenes` setting. Banned names is one line here; the old view's box takes one name per line (a comma works in both).
- **Settings rows in the new view.** The Settings overlay's Start, Look and Tools rows (budgets, panel style, glass strength, font, text size, sending) now have their values: the sdk's `settings` function carries the host's frozen `defaults` and `schema` (`sdk.settings.defaults`, `sdk.settings.schema`; the same constants as `HOST_SETTINGS_DEFAULTS` and `HOST_SETTINGS_SCHEMA`), which the overlay was reading and finding empty. Nothing else about `settings(id)` changes; no setter is added.
- **Settings writes and resets that did nothing now work (new view).** The Look rows (panel style, glass strength, font, text size, sending) and the Tools budgets (notes per reply, share of the context, change lines per reply) had `host.*` keys no handler answered, so a change failed with "There is no command called settings.set"; `ui/port/host-settings.js` now stores them as the host's own settings, the place the old view writes them (a choice row by its label; the Solid skin is not offered). The Reset button of World and time, Director, Chat extras, Models, Look and Tools failed the same way; `ui/port/resets.js` now puts that page's settings and switches back to their registered defaults (World: the calendar, map and time settings and the weather switch; Director: its rows in Story Director and NPC State; Chat extras: the two chatter rows and the three switches; Models: the two connections, one-at-a-time, the fallback kinds and the fallback switch; Look and Tools: their own rows). The old view had no page Reset, so these are the defaults its controls start from. The Add-ons page has nothing to set and draws no Reset. **Director is always listed:** when the host holds none of its settings it shows the defaults, as the mock does (a row whose feature is off is still left out when the feature list is read). **The RPG page reads Story Block's settings through the sdk,** as Money and Chat extras do (it read SillyTavern's extension settings directly); the Models page's Calls group still reads them directly. The duplicate "Add to party on a People page" line is gone.
- **Settings › RPG and fights in the new view.** The page is drawn with live values from Story Block's own settings: Difficulty (`rpgDifficulty`; a first switch to Custom copies the numbers in force into `rpgStandard`, as the old page does), Level cap, XP rate (50 to 300 in steps of 25), Practice per skill use, Companions who join, Set up a fight from my attack (`rpgPrecheck`), Most exchanges Auto plays (`rpgAutoCap`, 9 = until the end) and Story checks use your stats (`rpgChecks`); each change writes the same key as the old view's page, with the same limits, and **Reset RPG and fights to defaults** stores each default. Not built: the mock's "Odds on the fight board", "Combat rules" text button and the separate "Rolls" row (no setting or editor behind them; the old page's Combat rules box, Custom numbers and Gear switch stay in the old view; Custom numbers are not editable in the new view yet).
- **Settings › World and time in the new view.** The page now has its rows on the live host: Calendar (Calendar choice, Era, Months, Weekdays, Leap years), Weather (Weather comes from), Map (North, East, Km per map unit, Roads wind, Water and air speeds) and Time (Longest time jump, While-away recap, Deadlines, Quiet after replies and story days, Due soon, and, while the day digest is on, Days kept whole, Days kept in all and Remind the story of the last day). Each row reads and writes the same Story Director setting the old page does (`tracker.*`, `time.*`, `atlas.map.*`, `chronicle.digest*` under `story-director`; the weather row flips the `story-director.weather` feature), so a value set in either view is the same value; the host's own limits still hold a number. No prompt text changes. **Differs from the mock:** Months and Weekdays are two text rows (the mock has one Months and weekdays Edit button; the new view has no list editor); "Hours on the road per travel day" and "Coming up looks ahead" are not drawn because the engine has no setting for them (the pack's own drive hours and the Journal calendar's span are not settings); the Calendar choice says "From the pack" without the pack's name; the calendar fields are not greyed while the choice is From the pack (they are used only with Custom, as their hints say); the "Reset World and time to defaults" button is the page's shared one.
- **Settings › Money in the new view.** The Money page (Rules) now has its six rows with live values, as the mock draws them: Coins, smallest first (one line such as `copper: 1, silver: 10`, read by the old page's own list reader; a line that does not read is named under the row and nothing is saved), Show money as (Each coin / Smallest coin only), Money word, Plural, Short form and Price scale. Each row stores the same Story Block setting the old view's Money page stores (`coins`, `coinDisplay`, `currency`, `currencyPlural`, `currencyShort`, `economyScale`, through `settings.set('story-block', key, value)`), so a value set in either view is the same value; the page reads them at open (`ui/select/money-rows.js`, `ui/select/money-lines.js`) and writes through `ui/port/money.js`, which also answers the page's Reset button. The old page's check on the coins (a name used twice, a worth out of range) is not drawn in the new page; the store and money.js still read only the usable coins. Nothing the model is sent changes.
- **Settings › Chat extras in the new view.** The new Settings now has a Chat extras page: its module card (Choices, Inner chatter, Your look, moved out of Story Block's module on Start) and the Inner chatter group's two rows, "Send the last reply’s thoughts back to the story" and "Most chatter lines per reply". They read `sdk.settings('story-block')` and store `chatterInPrompt` / `chatterMax` and the three features through the same stores the old view writes (`ui/port/extras.js`), so a value set in either view is the same value; the number is clamped 1–10 by the schema. The mock's fourth switch, Trackers, is not drawn: Story Block has no such feature (trackers are on the Packs and trackers page). Scope "New chats" writes the same global stores until per-set defaults exist.
- **Settings › Packs and trackers in the new view.** The Settings overlay has the page (Setup, after Models). It lists the installed packs with their on/off switch and Remove (asks first), Import a pack file (a pack.json with its images, or a .zip) and Read from the character's lorebook, which install through the same code the old Packs panel uses (`packs/import-run.js`, now shared by both) and say what was installed, ignored or refused; the pack data modules of this chat (a switch uses the module with `dm.pin` and the hashes read now, as the old Enable button does; a module in use has no way off, so its switch is locked on); and this chat's trackers with their count of the cap. The tracker buttons (Edit fields, New tracker, From a template, Build it in the chat) close Settings and open Story › Trackers, where trackers are made and edited; they are not forms on this page. Packs are switched and removed by the port's new `packs.*` settings keys (`ui/port/packs.js`) on the same installed-packs store as the old view, so a pack changed in either view is the same pack.
- **Settings › Add-ons in the new view.** The new view's Settings has the Add-ons page (Setup, after Packs and trackers and before Tools), read live: **Installed modules** lists every module the sdk's `modules()` reports, each with its version and, when it is not running, why (`ui/select/addons.js`; it reads `sdk.modules()` each time the overlay opens, and says "none yet" with none). **Allow custom views** is drawn as a fact ("off · not available yet"), not as a switch: the suite has no custom-view host and no setting for it, so the page reads and writes no setting, and nothing about prompts changes. The old view has no Add-ons page; its Modules page (settings and versions of each module) stays where it is.

(2) The fight's end card shows what the fight paid: each member's practice chips, and "+N XP each" when every paid hero got the same XP (v1 pays by each hero's level, so with different levels the figure is left out until the owner decides how to show it); it reads the settle's receipt, so a rebuild, reload or Re-read draws the same card. (3) The Fight tab has the stance switch: the row shows the stance's name, "now: soak N%" for a Defence stance, and the switch. The switch starts where the last exchange left the stance, and Auto keeps a stance that was switched off, off (read from the steps before it). The line that says what switching off costs is not shown yet (it waits for the owner's wording). (4) The *Field medic* set's Mending now says it uses Mana (a heal always draws MP). (8) The ended fight's card has **Back to the story ›**, which goes to the chat tab; the fight still goes to the story with the next message.

- **NPC State: Refresh writes the slow fields (in progress, N8; stacked on N7).** The quiet catch-up Refresh is now rolling. After each captured reply at most K people are Refreshed (the new setting "NPCs refreshed per reply", 1 to 3, default 1; beside it "One-pass catch-up", N, default 4, 0 = off, now reads "each person waits N replies between Refreshes"). A person is eligible only if they were in the last N replies and N or more replies have passed since their last Refresh (a catch-up or the reader's own Refresh button); no more than K × max(1, N-1) catch-up Refreshes happen in any N consecutive replies (N=4, K=1: 3 per 4 replies); a person not seen in the last N replies is never taken. The slots go first to an eligible person not Refreshed for 3N replies (12 at the default), longest-waiting first, then to the most seen in the last N replies, ties by last Refreshed (oldest first); the people left over keep their place and lead next time. Each reply's journal entry keeps `roll` (who was in it, who its catch-up took, whose manual Refresh came after it); the order is read from the replies the chat stands on now, so a swipe, a swipe back, an edited Re-read, a middle delete, a rewind and a reload give the same order (an edit keeps the reply's marks; a catch-up Refresh that did not finish is not counted). The picker reads back 20 × N replies. A person never Refreshed waits from the first reply they were seen in (that reply counts), so a newcomer is due after N replies and overdue after 3N, like everyone else. The reader's own Refresh counts as the last Refresh whether it changed anything or not. The old per-session counter is gone. A failed one (a model error or a timeout) shows the same note as a failed fill-in, once per person; nothing is written, and a cancelled or discarded one (a chat change, a cancel) stays silent. **Refresh (catch-up and manual) also reads the messages SillyTavern has hidden** (`is_system` set by /hide, for example by a memory extension) inside its own window, as evidence, in [mN] order. Still not read: swiped-away and deleted replies, SillyTavern's own notes (anything it stores with `extra.type`: narrator, comment, help and the rest; the ones with no type are skipped by their own marks: a tool-call record by `extra.tool_invocations`, a help or safety note by its system avatar, an Image Generation message by a generated item in `extra.media`, a bias-only /sendas by having no text but its bias) and our own faded replies. Only the Refresh window changes; the narrator prompt, Fill-in and the reply scans still skip hidden messages. **Background quotes are stored** (`profileEvidence.background`, same caps as the other slow fields; a background with no quote of the window it read is left out of a Refresh, in the person's row and in the profile row alike, as rule 3 says; the quotes are not sent in a scan prompt, so scan prompts are unchanged). Its prompt is the owner-approved NSD11 text: it is the only writer of personality, speech, behaviorProfile, mannerisms, background, home base, key relationships and the relationship summary; the slow fields need quotes (in `profileUpdates.evidence`; the prompt asks for a background quote too, and it is stored; the wording of rule 3 is a draft awaiting the owner's OK) and two or more moments or an outright statement; the dossier JSON it reads gains the stored `tastes` (at most 12) and `ties`. It returns only changed fields: no `keep` states, no mood numbers, no `tastes`, no `keyRelationshipEdges` (a returned `tastes` key is ignored). The forwarding of Refresh tastes to the story is removed (`runtime-hosted-parts/tastes.js`, backed up). The background prompt golden changes for the five Refresh prompts only; the static golden is unchanged.
