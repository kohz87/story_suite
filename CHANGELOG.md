# Changelog

## 0.1.0

First release of Story Suite as one extension. It brings together what was Story Block, Story Director and NPC State Delta (now called NPC State). Their own changelogs, with every earlier version, are kept in `docs/history/packages/`.

- **One repository, one number.** Every place that carries the version (`package.json`, `package-lock.json`, `manifest.json` once it exists, `core/version.js`, the title of `README.md`, the head of this file) must say the same thing; `npm run release:check` fails if one disagrees, and `node scripts/release.mjs <version>` writes the number into all of them. A release is a version bump merged to main; releases are not tagged.
- **Combat Rules v1 is the only rules (combat v1-only job).** There is no rules chooser: every chat and every new sheet is made from the four v1 templates (`CHOOSER_TEMPLATES`, which the block chooser, the New character wizard, a joining companion and the Combat rules settings read). A new Character has seven stats 1 to 30 (STR VIT AGI DEX INT WIS CHA; LUK is gone), HP, MP and SP as numbers with their largest values worked out from the stats and the level, and one point per level; a Skills block has a type on every skill (attack, area, defence, evasion, movement, heal, support, utility) and practice 0 to 600, and a learn line that leaves the type out still learns an attack skill (the narrator is told `| type: attack|area|defence|evasion|movement|heal|support|utility` as required, without brackets). The four block descriptions the narrator reads are the v1 ones (Character, Skills, Foes, and the last line of Combat rules). The New character wizard builds v1: the stat steppers and radar run to 30, the line under them says HP, MP and SP, the Skills step has a Type column in place of Uses, and Create writes HP, MP and SP full with their largest values, so the first reply moves nothing. A companion the story adds (`+ party`, `best: wis`) is built the same way (every level one point; best stat and DEX first); a chat that already holds a Character made under the earlier rules keeps building the earlier blocks for a join and its Re-read, byte for byte (the party line's `about` is still read there), and keeps reading `best: luk`, until the earlier rules are removed. A character file reads WIS (a file with only LUK reads its LUK as WIS), skill types and ranks 0 to 6; a file written now has WIS and the type. The Party tab draws a v1 Character with its numbers and stats. The narrator's party-line grammar and the dice-bonus table say WIS where they said LUK; a check that names no stat and fits no skill word uses WIS. **The New character wizard makes You only, and "Who they are" is gone:** the Who step has no You or A companion choice (the name is the persona's), the Party tab's New character button shows only while the story has no You, and the v1 Character block has no About field (the wizard, the join card, the party payloads, the card and the Party tab no longer carry it; a file or a line that has `about` is read and the text ignored). A companion is made only through the join card: Add to party as before, or Edit first, which opens this wizard filled in from the join with every field editable. **A v1 fight against foes a lost or fled v1 fight left now starts from their bars:** `board/resume-v1.js` reads the chat's fight receipts, so when the story sets the same group again (same slot, exact name, level, tier and count) and the newest fight that covered the slot was lost or fled, the next fight opens with those HP; a won, unfinished or old-engine fight in between, a different group, a rewind or delete of the fight's reply, or another chat resumes nothing; a foe that fell stays down. The earlier engine is not removed yet (combat C11): a chat whose setup was made under it replays unchanged. **Things that only showed once a v1 chat could be made, fixed here:** a story check (`? roll`) in a v1 chat failed its step (a v1 character has no Soul Class, and the step hashed the missing one); a v1 Foes group counted as "no fight standing" (the Combat rules text was dropped from the prompt during a fight, the "No foes are set" note was told with foes on the sheet, and the pre-call and pre-check did not see the fight), so a filled v1 slot is now a standing group; a second companion in a chat of v1 Characters was built under the earlier rules (the chat's blocks were taken for old ones); the Skills screen explained the earlier roll formula and four ranks for a v1 skill (it now shows the stat, the rank and a seven-rank bar); the Spend points sheet's radar stopped at 20 and its line spoke of blocks and luck (it runs to 30 and says HP, MP and SP); a character file exported from a card of the earlier rules writes its LUK as WIS; a pack skill set or cast skill that names LUK is built with WIS, and a pack may name WIS. **Model-facing changes beyond the four block descriptions:** the party-line grammar says `wis` where it said `luk`; the dice-bonus table has WIS where it had LUK; a check that names no stat and fits no skill word is worked with WIS (it was LUK), and the words for luck, will and senses point at WIS; the v1 Skills learn line shows `type` as required (a line without it still learns an attack skill); the v1 Character sentence and the `+ party` line no longer mention who they are / `about` (a party line that still carries `about:` is accepted and the text ignored). **Not changed (the earlier engine's removal, combat C11):** Settings → RPG still shows the earlier Standard formula's footnote and its "10 to 20" stat maximum; Gear accessories still give LUK and a piece cannot give WIS; in a chat that already holds a Character made under the earlier rules a new fight opens an earlier setup, the wizard builds v1 blocks beside the earlier ones (the engine refuses a mixed sheet), and a join builds the earlier blocks.
- **Fresh start.** Nothing from the three old extensions is carried over: no settings, chats or sidecar files are migrated. See `docs/INSTALL.md` for the install steps and for removing the old three.
- **One bundle set.** The release and play builds pack the one extension from the root `index.js` and `manifest.json` into one bundle set (the RPG library and its screens stay separate lazy chunks; the People part is packed into the entry; the gate allows ten requests at load and counts any chunk the entry awaits at start; a build is 9 requests today, JS and CSS together). The bundle is a build output (`npm run release`, or `npm run play:dist` for a play build); it is not published yet, so installing from the repository's URL loads the source files one by one. In a build, `suite.css` and every `@import` it pulls in become one stylesheet (rules in the same order, fonts copied to the same paths); the source sheets are unchanged, and a source install still loads them through `@import`. The gate counts the stylesheet among the requests. Host imports (`extensions.js`, `script.js`, `utils.js`, `shared.js`) in `modules/people` are written for the depth of the file in the one extension folder, so a checkout installed as it is loads; the bundler keeps each at the depth of the file that names it.
- **Code layout.** `core/` (host), `modules/` (scene, inventory, data modules, assist, RPG, time, atlas, world, cast, arc, people), `ui/` (the new view and `ui/legacy`, the old view), `packs/`, `testkit/`. See `docs/codemap.md`.
- **The version people see is 0.1.0.** The console line and the Extensions drawer read `Story Suite 0.1.0` (`SUITE_VERSION`). The number modules and packs check their "needs Story Block 2.x" ranges against stays 2.33.0 as `HOST_VERSION` and in `StoryBlock.version`.
- **NPC State cannot stop the rest.** Its start (`startPeople`) runs through `startIsolated` after the modules: a failure is a MODULE_START Problem in Diagnostics and the new view's switch still appears.
- **Models page.** It has the Calls group (one call at a time, calls the reply waits on, the fallback call, People's output limit, what the fallback may write). The fallback call (the safety net that reads changes a reply forgot) now runs on the Background connection and is listed on that card, as the design says; before it ran on Quick helpers. This changes where that call goes for anyone who set the two connections differently.
- **Models page: Quick helpers list.** The Quick helpers card's fight item now reads "fight set-up from your attack: the pre-check (up to 20 s)", naming the call that runs as a quick helper (one item, not two). Text only; no call changes connection. The Assist safety net is not listed there: it runs on the Background connection and is covered by "the fallback call" on that card.
- **Quote sources read as #N.** A stored quote or memory that starts with a `[m12]` tag shows as `#12` (the message number SillyTavern shows) in the NPC State dossier: the relationship change reasons, the board tiles, the mood section, the Past section and the select view. Display only: what is stored, and the key a memory's date stamp is found by, keep the `[m12]` text.
- **Models page saves.** The queue switch, the fallback switch, what the fallback may write and each connection's pick are stored through the host's own settings and feature stores (`StoryBlock.writes`, for the new view only); the public sdk has no setter, and before this those controls saved nothing. The one-line note under a connection picker (no profiles, Connection Manager off) now has its style.
- **Story › Trackers works.** Show on Now writes the block's `show.card` (`dm.redefine`, as the old Blocks page did); Edit opens a sheet that changes values by hand (`dm.set`, only the fields you changed, numbers checked against their limits) and has Remove for a tracker this chat made (`dm.remove`, after a confirm); "Add from a template" makes one of the three built-in starters (`dm.define`; it starts hidden from Now). The commands are `tracker.pin`, `tracker.set`, `tracker.remove` and `tracker.add`, answered in `ui/port/trackers.js`. The Trackers list now reads the active block definition (`state`, field labels, `show`) instead of the pack's offer, so bars and Show on Now follow what is pinned. Not built: the old Customize/layout editor and editing a tracker's fields (the mock has neither); the Settings › Packs and trackers page is still not live.
- **No "Scene" tab for activities.** The Suite view's tab for an open interaction is named after the activity (its title, "Activity" if none, cut to 16 characters), shown only while one is open, with a small "Basic view" note when its module registered no renderer; Send and Discard work as before. A developer-only Template page (Settings → Tools → Developer tools, a per-device switch, off by default) shows the generic renderer on a sample for module authors. The word Scene stays for the Here card and the Scene sheet. The old view is untouched.
- **Fight pre-check names a tier.** On a Combat Rules v1 sheet (every new sheet) the pre-check's Assist prompt now asks each foe group for its tier (mob, minion, standard, elite, boss or apex, with examples; standard when unsure) and says the size rule (an even fight is at most 4 standard foes, a group of elites at most 3; bigger crowds are several groups). The reply shape gains `"tier"`. A sheet that is not v1 gets the old prompt unchanged.
- **The card's pack offer in the new view.** When the open character card ships a pack, the new view's Now tab shows it in the Needs you card (Install or Update, the "Also apply" tick, Not now; Dismiss on the result), and the chat's Needs you chip counts it ("1 pack offer"). It is the old panel's own offer, not a second one: the same controller answers both, so Install, Not now, the remembered "Not now" and the Diagnostics lines are the same. The Packs page is unchanged: its "Read from the character's lorebook" button is not wired to anything in the new view yet. With no offer, Now and the chip are unchanged.
- **Fixes.** The old view's `size.css` imported a stylesheet from a path that does not exist (a 404 at every start; the data-module screens lost their number-list, guild-tile and Enable all styles); `npm run check` now fails on any `@import` that names no file. The install guide names the Assist page's Extra calls for the default old view and says to run `npm ci`.
- **Deaths once (Key people).** The Director no longer teaches the narrator `- key Name | died`: the fixed prompt loses exactly two pieces (the `- key Name | died (anyone who dies)` grammar line and the last sentence of the Key people paragraph, `Write - key Name | died only for a death.`), and nothing else. The rest of the Key people paragraph (`Key people are the people {{user}} follows ...` up to `bring them back.`) stays, word for word. The `away` grammar line stays, and the away line in the tail does too. Deaths are read from NPC State (the same reading as before: `npc.known` / `npc.dossier`, and the Story Suite api). The `key` kind stays registered with the head `- key` so replies that already carry `- key Name | died` replay unchanged (swipe, swipe back, an edited Re-read, a middle delete, rewind, reload). Without NPC State a pinned person leaves only by Unpin (or by an old `- key` line when a reply is read again); no new death is recorded, so a dead person's own threads stay open; the narrator is not asked for one.
- **One Story Suite drawer.** Extensions shows one drawer headed `Story Suite 0.1.0` (the old "Story Block" header is gone). NPC State's settings are a section of it headed "NPC State", not a second "NPC State Delta v1.18.0" drawer; if NPC State mounts before the drawer exists, the drawer moves it in when it is drawn.
- **Character card picture without a party hero.** In a chat with no party hero the card shows the people row named like your persona, else your persona's avatar, instead of the initial; the card now draws a safe picture path (before, only the dev harness did).
- **The Fight tab in the new view.** A fight that is open now shows on the Fight tab of the Suite view (it was never reached before): the fight board is drawn by the activity host's fight renderer, you choose for every party member, and Send and Discard are the host's. Now's "Needs you" card and the chat row's fight chip open it; a sent or taken-back fight keeps the tab but no longer asks for you. Any other open interaction still has its own named tab. The fight's dice are the same after a swipe and back, a Re-read, a rewind, a middle delete, a reload and a chat change. The new view's Fight tab has no stance switch (Combat Rules v1 has none).
- **Tools page (new view).** Settings › Tools now shows, read from the live engine each time it is drawn: the budget bars and the text sent with the next reply (with the three budget rows under the bars, and the footer meter), the Inspector (a sheet: pick an older or newer reply; its changed lines, what code did, its problems and the state after; read again at each move), Problems (the turn's problems, and a blocked branch's "dossiers can't be restored" entry with the same two choices, the last 40 replies or the whole chat, which replaces the old banner on this page) and Diagnostics (Copy report). The Developer card and its Template page are unchanged. `StoryBlock.tools` is a new read-only handle for these (it also carries the rebuild button's call); the old view is untouched. Not built because nothing in the engine backs them yet: the Prompts rows (read, edit and reset the People and Arc planner prompts), Chat data (export and import this chat's suite data, "Rewind when a middle message is deleted", "Re-read changed branches") and Diagnostics › Pack events. Save points have no page in the new view (restart from a message instead).
