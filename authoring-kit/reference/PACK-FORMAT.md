# Pack format

A pack is a JSON object with an `id`, `version`, `requires` and `content`. Write `"format": 3`. Its `requires.suite` is a version range for the suite (`"^0.1"`; `requires.storyBlock` is the older name and still loads); optional `requires.capabilities` lists capabilities the pack needs, such as `scene`, `inventory`, `data-modules-v1` or `chronicle-lasting`. A pack whose `format` is newer than the suite reads is refused. Skills use the Combat Rules v1 words (types attack, area, defence, evasion, movement, heal, support, utility; `uses` sp or mp; ranks novice to legend), `content.rpg.formula` is `"v1"`, and `content.foes` lists foes by tier. Creatures, shops, recipes, quests, races, talents, presets, terms, ranks, crafts, layouts and screens are left out with a warning. See `docs/v2/PACKS.md` "Pack format 3".

Content can include places, routes, events, items, foes and data modules. A pack can also provide a calendar, weather, currency, screens and a start state, and a rank for the player's character: `"content": { "you": { "rank": { "label": "Guild rank" } } }` (label 1 to 30 plain characters, no `< > { }`; unknown keys under `content.you` are refused). Without it the game has no rank. See `DATA-MODULES-FORMAT.md` for data module fields and `LIMITS.md` for size bounds. The checker is the final authority: run `node check.mjs work/pack.json`.

Story Block 2.31.0 supports `content.names`: `{ "banned": ["Elara"], "river": { "regions": ["River"], "given": ["Wenna"], "family": ["Lockwright"] } }`. Each culture needs nonempty `regions` and `given`; `family` and `banned` are optional. `names` and `banned` are reserved culture ids. A Director with its names part may suggest given names for matching regions.

An optional top-level `ripples` object has `powers: [{ id, name, base, aliases?, factions?, givers?, npcs?, standing?, standingBase? }]` and optional `tiers`, `caps`, `standingModule` and `worldDirections: [{ event, favours, unless? }]`. NPC entries are `{ name, weight? }`. Story Director computes sway; see `docs/v2/PACKS.md` for scoped selection and fallback. An invalid names or ripples section is ignored and reported as a warning while the rest of a valid pack installs.

Once events may give the same `decision` slug to mutually exclusive alternatives. When earlier history changes, the host reselects that decision where its receipt was stored. Give the pack a `requires.storyBlock` range of at least `^2.31.0` when using these fields.


Event conditions can use `region(name, ...)` (Story Block 2.31.1): true when the scene's place is in any of the 1 to 16 named regions (exact names, as `query('scene.place').region == name`; false with no place). It replaces a chain of `||` over regions, so one event can cover several regions and fire once. Each name is at most 200 characters; the whole condition keeps its 1000-character limit.

With the Settings feature **World events** on (off by default), an event's `when` can also call `condition('name')` or `condition('name', 'ref')` (a world condition is active there), `active('event-id')` (that event happened and none of its `ends_when.any_of` `fired:`/`set:` anchors holds) and `fact('text')` (a Journal record mentions the text), and an event may carry the spec fields `kind`, `certainty`, `reach`, `severity`, `anchor_mode`, `where`, `requires`, `window`, `chance`, `likelier_if`, `less_if`, `pre_empted_by`, `outcomes`, `effects`, `ends_when`, `cooldown` and `summary`, in the strict grammar of the author spec §3: `chance` as "20% over the window" (or "30% per season" for a recurring event), odds modifiers as `×N` (a percent is refused), anchors (`set:` `cleared:` `fired:` `ended:` `lapsed:` `died:` `departed:` `fact:`, a season, `start`) in `requires`, a window's `after` (with an optional `+ duration`), `likelier_if`, `pre_empted_by` and `ends_when.any_of`, `effects.set` as "name@ref: 10 days" or `{ condition, at, for }`, `ends_when` as an object, and outcome weights `power:<name>` or `score:<name>`. Every place, route, region, realm, power, score, condition, cast member and event named must exist in the pack (a pack section that is absent is not checked). They are checked and kept; nothing acts on them yet. With the feature off they are not read and the calls are unknown. Not accepted in an installed pack yet: the pack check at install time still knows only the base calls and event fields, so such an event is refused when the pack is installed (a later job opens the pack check).

A pack can list a hand-written cast in `content.cast`: people with a look (the body) and what they wear, a voice, a personality with behaviour levers, mannerisms and how they treat the player character, a start (place, goal, routine), what draws them to the party, starting meters, stages, fields and secrets. Each may name a portrait image (`"portrait": "fenna.webp"`, WebP, PNG or JPEG of up to 10 MB, at most 32 per pack; Story Block makes one over 150 KB smaller when it imports it) that comes beside the pack: pick `pack.json` and the images together when importing, or ship one `.zip` with `pack.json` and a `portraits/` folder. A person may have a `birthday` (`"Icewane 27"`, optionally `"Icewane 27, 1204"`): a month name and day of the pack's own `calendar` (the month names must match it, so the pack needs a calendar); without one NPC State Delta chooses it. Story Block 2.32.0 is the first version that accepts `birthday` (older ones refuse it as an unknown cast field). A secret opens by a meter value (`meter` and `at`), by a story event (`when`), or by both, in which case it opens at whichever comes first; it needs at least one. See `docs/v2/PACKS.md` "The cast" for every field and `LIMITS.md` for the bounds.
